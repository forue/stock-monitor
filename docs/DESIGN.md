# 股票智能监控系统 — 设计文档

**版本**: v4.1
**日期**: 2026-05-12
**模式**: 常驻进程 + Cron 保活 + QQ C2C 直推

---

## 系统架构

```
常驻进程 (monitor-daemon.py)
  ├── 配置热加载 → 修改 config.json 无需重启
  ├── 交易时段判断 → 活跃 / 休眠，动态间隔
  ├── 多源数据获取 → 腾讯→东方财富→新浪→网易 自动降级
  ├── 波动指标计算 → 涨跌幅 / 振幅 / 量比 / 波动率
  ├── L1 初筛 → ≥2 条件同时满足 + 连续 2 次命中
  ├── L2 确认 → 量价共振 / 极端涨跌 / 极端放量 三路径
  ├── 场景分类 → 9 种异动场景智能识别
  ├── 阶梯式递增告警 → 趋势/反转/时间衰减规则推送
  └── 技术指标 → MA 金叉死叉 + RSI 过滤，独立于异动监控
```

- **保活**: `cron` 触发 `keepalive_check.sh`，调用 Python `is_trading_day()` 判断交易日
- **存储**: SQLite WAL 模式，30 天自动清理
- **推送**: QQ 开放平台 C2C API，AccessToken 缓存

## L1 初筛算法

设计目标：单一指标的瞬时波动多为噪音，真正的异动是"价量齐动"。

**至少 2 个条件同时满足** + **连续 2 次命中**：

| 指标 | 阈值 | 说明 |
|------|------|------|
| 价格波动率 | ≥ 1.0% | 现价偏离昨收的绝对比例 |
| 涨跌幅 | ≥ ±2.5% | 涨跌幅绝对值 |
| 量比 | 分时段动态 | 开盘 3.0 / 早晚盘 2.0 / 收盘 2.5 |
| 盘中振幅 | ≥ 2.0% | (最高-最低)/昨收 |

任意单一条件满足但不满足"至少 2 条件"规则 → 静默跳过。

---

## L2 确认算法

三种确认路径，**满足任一条即确认异动**，同样要求连续 2 次命中：

| 路径 | 条件 | 含义 |
|------|------|------|
| A. 量价共振 | 涨跌幅 ≥ 3.0% **且** 量比 ≥ 分时段阈值 | 主力资金介入 |
| B. 极端涨跌 | \|涨跌幅\| ≥ 5.0% | 忽略量比，优先告警 |
| C. 极端放量 | 量比 ≥ 6.0x **且** \|涨跌幅\| ≥ 1.0% | 异常成交量 |

### 分时段量比阈值

| 时段 | 时间 | L1 量比 | L2 量比 |
|------|------|---------|---------|
| 开盘 | 09:30-10:00 | 3.0 | 5.0 |
| 早盘 | 10:00-11:30 | 2.0 | 3.0 |
| 午后 | 13:00-14:30 | 2.0 | 3.0 |
| 收盘 | 14:30-15:00 | 2.5 | 4.0 |

量比公式：`当前成交量 / (近5日均量 × 已交易时间占比)`，最小有效时间 30 分钟。

## 阶梯式递增告警

替换固定间隔防重复，按价格偏离阶梯递增推送。规则优先级从高到低：

| 优先级 | 规则 | 条件 | 冷却 |
|--------|------|------|------|
| 1 | 极端行情 | \|涨跌幅\| ≥ 6.0% | 无冷却，不计入非极端上限 |
| 2 | 冷却保护 | 距上次 < 动态冷却 (波动率越高冷却越长) | 跳过 |
| 3 | 趋势延续 | 同向 + 偏离上次参考价 ≥ 2.0% | — |
| 4 | 方向反转 | 反向 + 偏离上次参考价 ≥ 1.5% | — |
| 5 | 时间衰减 | ≥ 30min + 偏离 ≥ 1.0% | — |

上限兜底：非极端 ≤ 8 次/天/股，绝对上限 ≤ 15 次/天/股（含极端）。

## 技术指标买卖信号

独立于异动监控，低频检查（默认 300s 间隔）：

| 信号 | 条件 | 过滤器 |
|------|------|--------|
| 金叉 (买入) | MA(fast) 上穿 MA(slow) | 收盘价 ≥ MA(filter) × 80% + RSI < 70 |
| 死叉 (卖出) | MA(fast) 下穿 MA(slow) | 无附加条件 |

每只股票可独立配置 `tech_analysis` 参数，未配置的使用 `tech_analysis_defaults` 全局默认值。同方向信号有 `min_signal_interval` 防重复，每日每只最多 3 次信号。

## 时间策略

| 时段 | 时间 | 状态 | 基础间隔 |
|------|------|------|----------|
| 开盘高波动 | 09:30-10:00 | 监控 | 3 秒 |
| 早盘 | 10:00-11:30 | 监控 | 8 秒 |
| 午间休市 | 11:30-13:00 | 休眠 | 300 秒 |
| 午后 | 13:00-14:30 | 监控 | 8 秒 |
| 收盘高波动 | 14:30-15:00 | 监控 | 3 秒 |
| 盘后/周末/节假日 | — | 休眠 | 300 秒 |

波动率 ≥ 2% 时降至 3 秒，≥ 1% 时 3 秒（在 high_volatility 时段降至 2 秒）。

## 数据源降级链

```
腾讯 (qt.gtimg.cn) → 东方财富 (push2.eastmoney.com) → 新浪 (hq.sinajs.cn) → 网易 (hq.sinajs.cn 兜底)
```

- 每源内置 3 次重试，1 秒间隔
- 自动降级，`fetch_free_data()` 透明切换
- 单只股票连续 3 次全源失败后进入指数退避冷却（60s → 120s → 240s ... 最大 3600s）

---

## 配置热加载

`lib/config.py` 通过 `os.stat().st_mtime` 检测 `config.json` 变化，每次主循环迭代自动检测并重载。无需重启进程即可调整阈值或添加股票。

---

## 单实例保证

- 启动时检查 `/tmp/stock-monitor.pid`，通过 `/proc/{PID}` 判断进程存活
- 存活则拒绝启动（报错退出）
- 退出时通过 `atexit` / `finally` 清理 PID 文件
- 信号处理 (SIGTERM/SIGINT) 设置 `running = False` 标志，由主循环检查优雅退出

---

## 故障降级

| 故障类型 | 处理策略 |
|----------|----------|
| 数据源全部不可用 | 跳过该股票本轮，连续失败触发指数退避冷却 |
| QQ 推送失败 | 写入 `alerts.json` + `qq-alert-queue.jsonl` 文件兜底 |
| 配置文件损坏 | 使用内置 DEFAULT_CONFIG 继续运行 |
| 数据库写入失败 | 日志记录，不中断主循环 |
| 单只股票异常 | 独立 try/except，不波及其他股票 |
